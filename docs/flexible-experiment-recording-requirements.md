# 灵活实验记录：第一阶段需求基线

日期：2026-10-17

状态：根据本轮需求讨论整理的产品需求基线；代码已接入，实际交付与验收边界见[实施记录](flexible-experiment-recording-delivery.md)。本文覆盖战略一当前阶段，不是数据库或接口的最终设计。

实施方案见：[模块探查与实施计划](flexible-experiment-recording-implementation-plan.md)。

## 1. 产品目标与优先场景

主要目标是帮助原作者在未来复现实验：原作者不能忘记当时实际使用的条件、执行的操作、观察到的现象及取得的结果。暂不以陌生研究者完全脱离原作者指导即可复现作为基本验收标准。

第一阶段优先场景是当天实验结束后的整理总结，例如晚上通过对话、手写记录照片和文件整理当天的实验。不将“现场记录”限定为实验进行中逐步操作、逐步录入。

用户无需选择模板，也无需先选择合成或测试类型。LLM 根据本次内容提出子字段和呈现方式，用户可手动编辑。合成、测试用于需求举例，不设为强制产品分类或代码枚举。

本阶段不建设模板选择、模板保存、模板库或按实验类型预设字段的流程。未来通过文献生成的参考型实验记录属于战略二，不在本阶段以模板功能替代。

## 2. 固定主结构

记录基本信息位于主板块之外，继续管理编号、标题、日期、作者、状态等信息；本阶段不因内容灵活化而取消现有身份、权限、版本、附件和更新记录。

主内容固定为三个板块，顺序固定：

| 主板块 | 定义 | 可选子字段示例，非预置必填清单 |
| --- | --- | --- |
| 实验条件 | 本次实验实际使用的对象、资源和起始条件，以及理解本次实验所需的背景 | 实验目的、药品列表、仪器列表、起始样品、已有溶液、药品用量计算、参考方法 |
| 实验过程 | 实际执行的操作及过程中发生的事件 | 操作流程、过程参数、过程现象、操作偏差、临时处理 |
| 结果与分析 | 最终获得的结果、现象及作者对结果的解释 | 产物信息、测量数据、谱图、结论、问题、后续想法 |

“结果与分析”中的分析指允许记录用户的解释，不表示授权 LLM 自动开展分析或补写结论。明确请求的模型分析仍走现有分析工作流。

三个板块不要求全部有内容，不以补齐固定栏目作为保存条件。过程中出现的现象可放在实验过程，最终现象可放在结果与分析；按内容语境组织，不重复生成两份可独立修改的同一事实。

“实验条件”记录实际条件，与尚未执行的实验计划不同。未来计划与执行分别记录，不能相互覆盖；第一阶段不实现实验计划模块，不创建占位计划板块。用户提供的计划性文字必须保持计划语义，不得转写成已执行事实。

## 3. 子字段仅一层

唯一允许的字段层级为：记录 → 固定主板块 → 子字段 → 字段内容。

子字段下不得再创建子字段、子板块或递归分组。复杂信息应展平为并列子字段，或在单个字段内用表格、流程图、富文本、注释与备注表达。

例如：

```text
实验条件
  药品列表          表格内容
  仪器列表          表格内容
  共用溶液          表格及备注
  药品用量计算      公式及计算过程
实验过程
  制备流程          物质节点与动作连线
  操作补充          富文本内容
结果与分析
  产物信息          表格内容
  结果图片          图片及说明
```

溶液本次配制时，可直接作为实验过程中的操作。很久以前批量配制或组内统一配制的溶液，可在实验条件中作为已有资源记录。两者均不引入嵌套字段。

表格行列、流程图节点和连线、计算表达式具有各自的数据结构，这些是字段内部的内容，不属于增加字段层级。不得借字段内部结构重新提供任意递归子表单。

子字段名称不要求统一成预设词表。字段应具有稳定身份，使改名、排序和内容编辑不丢失原值、来源及修改记录。具体身份与存储形式留待技术设计。

## 4. 字段类型与呈现

内容类型与呈现方式分别管理：内容表达事实及其关系，渲染器决定如何显示。同一份内容能以适合它的其他方式显示时，不另行保存一份独立事实副本。

| 内容 | 呈现要求 |
| --- | --- |
| 目的、说明、现象、备注 | 富文本、段落、列表 |
| 药品、仪器、样品、测量数据 | 可编辑表格 |
| 操作过程及物质变化 | 可编辑流程图；有明确顺序时可提供相应步骤视图 |
| 公式与计算过程 | LaTeX 排版、变量说明、代入过程和结果 |
| 图片和原始文件 | 图片、图集、附件列表及说明 |

用户和 LLM 可选择系统支持的、与内容兼容的呈现方式。不是让 LLM 生成并执行任意 HTML 或 JavaScript。第一阶段无需任意可编程渲染器、通用图表设计器或完整表单设计平台。

只改变视觉呈现且不改变内容类型或语义时，不视为字段结构变更。转换会丢失信息或改变含义时，先展示变化供确认，不能静默转换。

公式渲染不等于计算验证。若产品执行计算，应使用确定的计算程序，保留输入、单位、公式和结果；计算所得必须与实际称量、实测数值区别表达。原文缺失的输入不得由模型编造来完成计算。

## 5. 流程图语义与编辑

流程图的矩形节点表示药品、物质、样品或中间状态，例如溶液、混合液、前驱体、干燥后的粉末。不要求每个节点都有正式样品编号。

有向连线表示动作，例如混合、加热、搅拌、离心、洗涤和测量。原料汇合、产物分流以节点和连线关系表达，不仅靠文字排版暗示。不得自动补造未被记录的中间物质或反应产物。

动作连线须能保存和单独编辑参数，如温度、时间、转速、用量及备注；参数适应本次动作，不要求每个动作填写同一组参数。不得只保存一张流程图图片，或只保存无法可靠局部编辑的图形生成代码。

完全重复的动作直接在线条文字中注明，例如“洗涤，重复 3 次”，第一阶段无需循环控制执行语义。

用户应能增删节点和连线、修改节点内容、修改动作及参数；具体编辑交互与布局算法在技术设计中确定。字段内部的节点或动作变化属于内容编辑，不等同于增删主板块下的子字段。

实验条件与过程中的物质、样品可通过流程图关系表达，不要求用户额外填写一套关系表。若同一对象被多个视图展示，修改后应保持一致；不以图形坐标或显示名称作为唯一对象身份。

流程图用于记录和阅读，不是自动控制仪器的可执行工作流。

## 6. 输入与原生多模态

支持通过文字对话、手写记录图片及 PDF 组织本次记录。第一阶段关注当前一次或少量实验的整理，不承诺大规模历史库批量处理效率。

图像与手写内容直接交给支持视觉的原生多模态模型；不建设独立 OCR 为必经环节。页面渲染、方向调整、分辨率处理、裁切及分批提交属于输入准备，不等于另建识字系统。具体格式与单次容量在技术设计和样本验证后确定。

扫描 PDF 需要把页面图像送达模型，不能仅提取空文本后声称已读文件。不支持视觉的模型必须明确说明能力限制。

保留原始输入、附件与整理结果的来源。第一阶段至少能回查文件及页码；精确区域定位作为增强能力，不能把未经验证的模型坐标显示成可靠定位。

无法识别、存在涂改冲突或缺少单位时保留不确定性和原件，不凭常识补全。未能结构化的内容可放在适当字段的注释或备注中，不得静默丢弃。

一组资料可能对应多条实验；系统可以提出归属与拆分建议，不能仅按“一页一实验”机械处理。面对具体归属不明时再提问，不要求用户事先完成复杂分类。

## 7. 写入与结构变更权限

### 7.1 普通内容直接写入

用户提供的新信息可直接写入已有字段，随后告知写入结果，不为每次普通补充增加确认步骤。保留原始输入、更新记录与可追溯的历史值，提供撤销或恢复修改的能力。

“直接写入”不等于盲目覆盖。当前内容与新信息存在明确矛盾，且用户未明确表达修正或替换时，先求证；用户明确表示“刚才写错了，改为……”时，可按明确指令更正并告知。

原始笔记、模型整理结果和模型解释应可区分。没有结果或结论不构成编造它们的理由。

### 7.2 字段结构变更必须人工确认

LLM 可提出结构方案，但以下操作属于高权限：新增或删除子字段、字段改名、跨板块移动、合并或拆分字段，以及改变内容类型或结构。

必须展示具体方案或差异，由用户手动确认后应用。不能仅凭模型在工具参数中声称“用户已确认”执行。确认应绑定具体方案及目标记录版本，避免确认后方案被替换。

初次组织字段也适用此规则：可将整份初始结构作为一批方案确认，无需逐字段弹窗。确认前允许保留原始输入和候选内容；用户输入不得因等待结构确认丢失。结构确认后，普通内容补充按直接写入规则执行。

用户本人在编辑器进行的结构操作属于手动操作，不需要再次按“LLM 建议”重复确认。

## 8. 历史引用与提问边界

### 8.1 有依据的沿用

沿用当前工具支持的历史搜索和读取能力，不把父 Agent 的读取范围收缩为“只能看当前记录”。是否可读取仍由账号作用域、Agent 角色及现有工具权限决定。

当用户表明沿用某次实验的条件，且引用对象、沿用范围已明确并成功读取，LLM 可直接采用相应条件，完成后告知沿用了什么以及来源，无需再询问一次。

如果用户只说模糊序号或搜索存在多个候选，仍须先确定引用对象，不能猜编号。搜到一个相似实验不等于获准将其条件写成本次事实；本轮“直接用”适用于有明确沿用语义的条件继承。

用户说“与上次一样，但温度改为……”时，继承适用的未变条件，明确变动优先。历史结果、现象和结论不是本次结果，不因沿用条件自动复制。关键继承应记录引用实验及所读取版本，便于复现和解释。

### 8.2 提问必须有具体依据

- 当前记录内部存在明确矛盾，可以提出具体问题。
- 当前语境与已确认引用记录有冲突，且不能由用户明确给出的差异解释时，可以提问。
- 涉及指代、归属、笔迹或数值确实无法确定时，可以针对该不确定点提问。
- 不因模型认为某类实验“通常需要温度、时间、转速”等而判定记录缺失，也不据此持续追问。
- 不使用模板必填项或实验类型优先参数清单驱动问询。
- 未知内容保持未知；无论提问与否，都不得无依据写入。

不设置“所有关键固定字段齐全才允许保存”的门槛。保存现有信息不等于宣称其完全具备复现条件，也不生成缺乏依据的复现完整度评分。

## 9. 已查阅的现有工具与实现边界

查阅范围：`lib/core/agent_tools.py`（工具说明与参数）、`lib/agent_v2.py`（工具执行及角色/模式列表）、`lib/core/prompts.py`（现有工作规则）。以下是现状与需求的区别，不表示新能力已实现。

| 现有能力 | 现状 | 本阶段衔接要求 |
| --- | --- | --- |
| `search_experiments`、`list_experiments` | 搜索、列出可访问实验 | 保留，不额外施加仅可读取用户事先点选记录的限制 |
| `read_experiment` | 读取当前数据；`as_reference=true` 登记引用 | 适配新内容结构，继承前读取可靠数据 |
| 聊天历史搜索、读取、翻阅工具 | 可查阅历史会话 | 可提供上下文；具体实验参数优先核对当前记录，不能以旧对话覆盖新数据 |
| `update_schema` | 写入记录线程的固定字段状态 | 需要适配灵活字段，区分内容更新与待确认结构变更 |
| `generate_record` | 根据记录线程状态生成并保存 | 移除固定字段齐备假设，不引入模板前置流程 |
| `modify_experiment`、`read_update_log` | 增量修改已存记录，保存修订及更新日志 | 普通内容按授权直接更新；结构修改须有服务端执行的人工确认约束 |
| `search_attachments`、`read_attachment` | 搜索附件、读可提取文本；图片直接进入视觉模型 | 延续原生视觉，补足扫描 PDF 等页面视觉输入与来源信息 |
| `manage_attachment` | 用户语义明确或确认后关联附件 | 保留此语义，不把读取附件等同于自动关联到实验 |
| `manage_archive` | 归档或恢复，非彻底删除 | 保留现有行为，本阶段不增加永久删除 |

`load_reference` 定义仍在源码中，但不是当前模型工具列表中的新调用入口；读取并登记引用使用 `read_experiment(as_reference=true)`，不能根据残留定义错误规划工具能力。

现有主 Agent 按自由、记录、分析模式提供不同工具；分析模式不向模型提供实验内容修改工具。实验编辑子 Agent 的读取、修改和附件操作受当前实验作用域限制；分析审阅子 Agent 用于只读核对，报告读取受当前报告限制。本需求不借字段重构扩展这些角色权限。

当前修改实现具有修订冲突检查和日志，但没有灵活字段结构变更的人工确认机制；现有工具说明、提示词中的固定 Schema、类型优先参数和强制缺失追问不代表本需求已满足。

后续需同步调整工具参数、服务端校验、提示词、页面编辑器、渲染器及分析读取；不能只改提示词就宣称完成权限或数据模型升级。

## 10. 本阶段不做

- 实验模板系统，包括选择、保存和推荐模板。
- 强制划分合成/测试类别及按类别固定字段。
- 独立实验计划模块、计划执行对照工作流。
- 完整的实验中实时操作记录体验、仪器联动或自动采集。
- 大规模历史资料批量导入、批处理吞吐和专项效率优化。
- 文献库、文献阅读生成参考型记录及文献联合分析；它们属于战略二。
- 独立 OCR 必经流程、通用可编程表单平台、自动执行实验的流程引擎。
- 凭世界知识补齐参数、结果或结论；以固定缺失清单驱动追问。

不做批量效率优化不等于排斥手写资料；当前一次实验的照片/PDF 仍属于本阶段核心输入。

## 11. 验收场景

1. 当日整理：用户晚上以对话和手写照片提供实验信息，无需选择模板或实验类别，即可开始整理到三个固定板块。
2. 初始结构：LLM 提出一层子字段及呈现方案，用户可修改并批量手动确认；确认前后原始输入均不丢失。
3. 普通补充：在已有“过程现象”字段中增加用户刚提供的浑浊现象，直接保存并告知，不重复要求确认。
4. 结构修改：LLM 建议将某字段移到其他主板块或删除字段时，未经手动确认不能实施；批准方案之外的变化不得夹带执行。
5. 扁平内容：药品、仪器、已有溶液以并列子字段的表格表达，不出现子字段下的嵌套分组。
6. 流程编辑：图中物质及中间状态为矩形节点，动作在线条上；用户能修改动作温度、时间等参数，刷新后内容与关系仍保持。
7. 重复操作：三次相同洗涤可显示为线条上的重复次数说明，不强迫建立复杂循环结构。
8. 引用继承：用户明确说条件同某条可确定的历史实验时，读取后直接继承适用条件并告知来源，不再确认一遍，不复制旧实验结果。
9. 明确差异：用户说“同上次但温度改为 80℃”，按明确差异整理，不将它误判成必须追问的矛盾。
10. 实际矛盾：同一步骤出现无法解释的 80℃ 与 180℃ 时，指出依据并求证，不擅自择一或覆盖。
11. 不凭常识追问：记录没有转速且无上下文要求时，不因“搅拌通常有转速”而强制询问或填入默认值；现有信息可保存。
12. 不确定识别：笔迹或单位不可辨时保留原件及疑问，不生成看似确定的数据。
13. 公式呈现：用户提供的用量计算可用 LaTeX 显示，公式与输入可编辑，计算结果与实测值区分。
14. 权限及兼容：保留账号隔离、角色作用域、版本冲突保护、附件与历史追溯；已有固定字段记录仍可读取，不在需求阶段直接破坏迁移。

## 12. 技术设计阶段再确定的事项

数据存储格式、旧数据迁移映射、编辑器组件、流程图引擎、公式计算范围、模型输入容量及布局算法属于后续技术设计。本需求不预先绑定库或模型，不要求立即改写现有代码。

数据与权限约束必须先满足，再选择具体实现；这些实现选择不应重新引入模板、递归字段、固定实验类别或无依据补写。
