# 灵活实验记录实施与验收记录

日期：2026-10-17

本轮交付三板块灵活正文的代码实现与隔离环境验收。真实手写识别质量仍待授权样本评估；不能据此宣称已经兼容所有实验室的手写资料。需求依据见[需求基线](flexible-experiment-recording-requirements.md)，原实施顺序见[实施计划](flexible-experiment-recording-implementation-plan.md)。

## 1. 已接入的使用流程

1. 在实验列表中选择“新建记录”，创建服务端草稿。无需选择模板或实验类型。“继续草稿”可重新打开未发布草稿。
2. 正文固定为实验条件、实验过程、结果与分析。各板块允许一个层级的自定义字段，可增加、删除、改名、排序和跨板块移动。
3. 字段支持文本/Markdown、动态列表格或卡片、物质与动作流程图或步骤视图、LaTeX 公式、附件。流程图节点表示物质或状态，动作线保存可编辑参数和重复说明。
4. 对话整理创建同样的草稿。模型提出字段结构方案后暂停；用户在卡片中查看前后内容，批准、拒绝或调整方案。调整会产生新方案并废止旧方案，模型没有批准工具。
5. 已批准字段中的内容补充走普通修改。新增字段、改字段名称/类型、移动字段和改表格列结构需要新方案。用户主动在编辑器中改结构可以直接保存。
6. 完成整理发布正式记录，直接保存批准后的正文，不再进行固定字段二次提取。草稿和方案均存储在服务端，刷新或重启不丢失已保存内容。

尚未点击保存的手动编辑只保留在当前页面内存中；不宣称页面关闭后自动恢复。发生版本冲突时保留本窗口编辑，不覆盖另一窗口的提交。

## 2. 代码与数据边界

| 部分 | 实际实现 |
| --- | --- |
| 正文契约 | `lib/core/record_document.py`：严格校验三板块、字段类型、唯一 ID、图端点、表格列及来源引用；拒绝嵌套和未知字段 |
| 唯一写服务 | `lib/services/record_document.py`：版本检查、审批绑定、幂等操作、账号隔离、发布与恢复 |
| 存储 | `lib/repositories/sqlite_record.py`：草稿、结构方案、请求去重、完整正文版本；共享连接事务保证正文/日志/版本原子提交 |
| 兼容投影 | `lib/services/record_projection.py`：旧正文只读映射，搜索摘要，分析事实投影；视图或图形位置改变不当作事实改变 |
| Agent | `lib/core/record_tools.py`、`lib/services/record_agent.py` 与 `lib/agent_v2.py`：主会话/实验子会话工具、目标范围及服务端草稿状态 |
| 原生多模态 | `lib/services/attachment_reader.py`、`lib/llm.py`：图片和 PDF 页面渲染后送多模态模型，返回页码、来源及未读范围，不走 OCR |
| React | `frontend/src/features/record-document/`：正文编辑与呈现、草稿、方案卡片及完整版本恢复 |
| 打印 | `frontend/src/features/print/record.tsx`：与页面共用正文渲染器，包含表格、SVG 流程图、公式及原始记录 |

SQLite 自动增量迁移到版本 7，保留旧实验列，增加 V2 正文、摘要和搜索投影。V2 正文是唯一可编辑事实来源，旧固定列不反向覆盖它。完整版本从本次支持的新操作开始记录，不能恢复此前只有摘要日志的历史内容。

旧记录读取不会自动改写。详情页提供升级预览，用户批准后转换；旧计划文字保留计划语义，不把默认“无异常”当作实验事实。旧 save-json、固定提取确认等入口不能覆盖 V2 正文；旧导入工具校验格式后才写入。未运行任何真实旧离线库导入。

列表、正文关键词搜索、对比、分析输入、引用、YAML 导出和打印已接入新正文。仍被字段或来源引用的附件不能直接解除关联，避免断链。用户文献管理、实验计划和历史批量导入不在本轮新增范围内。

## 3. 主要 HTTP 契约

接口均要求登录，按当前账号隔离。以下路径相对于 `/api/v1`。

| 方法与路径 | 作用 |
| --- | --- |
| `POST /record-drafts`、`GET /record-drafts` | 创建草稿、列出未发布草稿 |
| `GET /record-drafts/:id`、`GET /experiments/:id` | 正文、当前版本和待处理结构方案 |
| `POST /record-drafts/:id/operations`、`POST /experiments/:id/operations` | 人工保存，要求 `expected_revision`、`request_id`、`document`；可附基本信息 |
| `POST /record-drafts/:id/structure-proposals`、实验对应路径 | 提出完整结构方案，绑定当前版本 |
| `GET /structure-proposals/:id` | 读取服务端规范方案及哈希 |
| `POST /structure-proposals/:id/resolve` | 人工决策，要求 `decision`、`proposal_hash`、`base_revision` |
| `POST /record-drafts/:id/publish` | 发布，要求当前版本和请求标识 |
| `GET /experiments/:id/revisions`、`GET /experiments/:id/revisions/:revision` | 版本列表与完整快照 |
| `POST /experiments/:id/restore` | 恢复为一个新版本，保留既有历史 |
| `GET /record-attachments` | 当前账号附件元数据 |
| `GET /experiments/matches?q=…` | 含 V2 正文投影的关键词匹配 |

冲突返回 409，非法正文返回 422；接口不接受由调用方指定“绕过审批”标志。Agent 使用服务层普通写入权限，不调用人工 operations/resolve 路径。

## 5. 仍需验收的内容

1. 使用真实授权样本评估中文手写、涂改、不清晰单位、多页扫描 PDF，以及复杂汇合/分流图；逐项人工对照原件。当前 PDF 测试验证真实渲染和页码数据流，内容识别使用替身。
2. 在实际配置的多模态供应商上确认图片/PDF 读取、结构化工具输出及失败提示。模型只根据世界知识判断的缺项不得写入；该行为需要真实对话评估持续检查。
3. 系统打印对话框和最终 PDF 分页尚未操作验收；本轮验证的是浏览器打印正文页面。
4. 生产切换前按原部署文档做备份与恢复演练，再逐步启用。未批量改写用户旧库，文献深度集成另行实施。

## 6. 2026-10-18 版式与流程图调整

子字段标题与正文共用一个完整阅读区域。宽区域采用标签/内容双列，窄区域上下排列但不分成独立灰条与白底。根据最终反馈，保留板块外框、黑色标题带、蓝色强调线和黄色编号，仅去掉子字段的闭合边框。板块内部采用连续浅底、对齐和细分隔，避免大框套小框，同时保留原板块视觉风格。表格使用独立正文表格样式，避免继承旧三线表的粗线。共享设计变量限定规格，不要求每个容器都画框；流程图物质框保留内容语义。聊天工具卡与审批卡仍共用外框、阴影、间距及字号角色，约束已补入前端 README。

流程图根据所在容器宽度而非浏览器总宽度自动排布。节点尺寸跟随文字，长名称和动作条件自动换行；横排放不下时竖排，分支过多则分行。物质框表示物质/中间状态，动作仍在线上，多个输入共享一份动作标签与参数。连线通过行间空隙和外侧通道绕开折行后的节点。布局变化不改写事实或持久化屏幕坐标，不靠缩小整张图或裁切图形解决宽度。

窄区域表格转成带列名的纵向条目，超过四列的表格也采用纵向排版；代码/长编号换行，长公式完整适配容器宽度。移除了正文图表的横向滚动容器。

审批卡原先因普通气泡的内容收缩规则被挤成细长条，现占用聊天栏可用宽度；待审批时展开，处理后默认折叠、可重新查看。回执改成明确的草稿/记录修订语义，新草稿回执不再把内部草稿 ID 当作正式实验编号。历史回执不改写其已存储数据。

验证：前端 84 项测试及生产构建通过，相关后端 15 项测试通过。新增图布局测试覆盖横竖切换、多输入/输出、长名称、循环、边界和连线不穿过节点。隔离浏览器使用简单记录与六输入/三输出合成记录验证，包含手机编辑态；实际记录未转换，未调用真实模型。

## 7. 2026-10-18 编辑页修复与整理

修复编辑态正文消失：原生 fieldset 包裹采用 inline-size 容器查询的正文时，在实际 Chromium 页面中将正文及三个板块压成零高度。改用普通 div 承载编辑内容，通过 inert 在提交中阻止编辑。正文数据并未丢失。

基本信息统一为带可见标签的两列表单，标题占整行。保存、取消和未保存状态集中在顶部工具条，并随面板滚动保持可见。编辑期间隐藏附件管理，明确保存或取消后继续管理附件。保留已接受的板块外框、黑色标题带和连续浅色正文。

字段默认显示内容预览，每次展开一个字段编辑。新增字段入口、字段备注及改名、换类型、移动、删除等结构操作分开收起。表格以单元格多行输入编辑，列管理单独展开。流程图支持点击或键盘选择物质/动作，也可使用下拉框；只展开所选对象的名称、备注、输入/输出及参数，避免同时铺开所有对象的表单。交互 SVG 节点单独约束样式，避免继承全局按钮的白字和大写规则。

验证：前端全量 88 项测试通过，最终调整后编辑相关 8 项测试再次通过，TypeScript 检查与生产构建通过。新增测试覆盖切换字段保留未保存内容、动作参数及物质编辑、保存/取消、409 冲突保留草稿。浏览器使用隔离合成记录验证参数修改、保存、刷新持久化及取消恢复；在 390px 和 320px 宽度验证简单流程、六列表格和六输入/三输出流程的编辑，页面及编辑正文未出现横向溢出，流程自动纵排。验收参数修改后已恢复原值，保留相应修订历史；未操作用户真实实验数据。

附件区按阅读和操作分层：默认展示已有附件与“添加附件”入口，上传表单按需展开。文件选择、格式/大小说明及可选标题纵向排列，连续浅灰底区分操作区域，提交按钮独立置于底部。桌面按钮右对齐，手机按钮占整行，控件高度统一为 44px。移除重复的未选择提示及上传区域的技术说明；未选择文件时不能提交。相关 7 项测试和生产构建通过，真实浏览器验证桌面、390px 手机布局及长文件名选择；验收文件未上传。
