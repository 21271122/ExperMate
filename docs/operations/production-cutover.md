# 正式部署与数据切换清单

本文对应“部署与正式切换”，是后续执行清单；当前没有连接或修改正式服务器。

## 1. 确定部署目标

需要明确服务器系统、地址和运维登录方式，服务仅内网访问还是公网访问，是否有域名、HTTPS 反向代理，以及数据目录和备份位置。公网访问需要可用的 HTTPS 入口；内部部署也应按实验数据的保密要求配置访问范围。

当前代码要求单进程多线程和持久磁盘。不要配置多个 Gunicorn worker、多个容器副本或把 SQLite 放在临时容器文件系统。浏览器直接访问服务器，不要求用户电脑运行 Python。

## 2. 准备可追溯的发布版本

- 将本轮迁移与清理代码提交到 Git，并确认使用的发布提交。
- 在服务器安装 Python 3.12+ 与项目依赖，构建或部署 `frontend/dist/`。
- 一同部署 `static/`、`ai-shell/`、`templates/` 等资源；Node.js 仅在构建前端时需要。
- 为服务建立独立操作系统账号，限制代码、配置、数据库、恢复密钥与备份目录权限。

## 3. 配置服务端

- 指定持久数据目录和配置路径，设置模型服务商、模型名、API Key。
- 创建正式管理员账号，确定是否允许公开注册。
- 固定并保存 JWT 签名密钥；保管账号库与恢复密钥。
- 需要找回密码时配置 SMTP 并实测收信；未配置时该功能明确不可用。
- 如使用 SQLCipher，在目标环境验证驱动、密钥与备份恢复；不启用时按明文服务端存储保护磁盘。

## 4. 接入运行与网络入口

Linux 部署示例使用 Gunicorn 单 worker、多线程，systemd 负责开机启动、异常重启和日志管理。Nginx 或已有代理负责 HTTPS、Host 与协议头、关闭 SSE 缓冲和设置长请求超时。

仅经过受控代理时设置 `TRUSTED_PROXY_HOPS`；防火墙限制后端只由该代理或允许的内网访问。并发模型请求与 SSE 会占用线程，线程数应在真实负载验收后确定。具体示例见[部署说明](deployment.md)。

## 5. 迁移前备份与演练

停止旧服务写入，备份旧数据目录、配置、账号与恢复密钥，记录旧版本提交。先在隔离目录导入一次，核对数据完整性，再安排正式切换窗口。

用户已选择稍后手动指定归属账号；在账号确认前不导入真实离线库。确认后用 `import-workspace` 导入空账号，检查源/目标备份与导入清单。模型配置和自定义模板另行显式迁入。详见[手动导入说明](../server-runtime-migration.md#5-手动导入旧-sqlite-工作区)。

## 6. 在目标服务器验收

- 健康接口、首次登录、登出与过期会话。
- 两个账号的实验、报告、附件、会话和搜索隔离。
- 管理员模型设置，以及真实模型的普通对话、流式回复、工具执行和分析任务。
- 附件上传、下载、预览、打印与大请求限制。
- 多窗口实时更新、编辑冲突、刷新与服务重启后的历史恢复。
- HTTPS Cookie、代理后的同源写入、SMTP、运行日志和备份恢复。

本地自动化和模型桩验收不能代替这一阶段的真实网络、模型和邮件测试。

## 7. 正式切换与回退

验收通过后才切换域名或访问入口，通知使用新的服务器地址；切换窗口内停止旧端写入，避免两套数据继续分叉。观察应用错误、模型失败、附件访问和磁盘增长。

保留旧版本及备份。需要回退时先停写并备份新库，检查切换后新增记录的去向，再恢复约定的版本和数据，不能直接用旧备份覆盖新产生的数据。

## 8. 日常运行

安排数据库与账号材料的成套备份、异地副本、保留周期和恢复演练；监测磁盘、错误日志与模型调用费用。当前没有持久任务队列，异常重启能恢复已保存会话，但可能中断正在生成的请求。这一限制需纳入验收与使用约定。
