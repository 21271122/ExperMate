# 数据、备份与恢复

> 状态：当前实现
>
> 源码依据：`app.py`、`lib/attachment_store.py`、`lib/repositories/`、`lib/e2ee/`

## 数据在哪里

| 内容 | 主要位置 | 说明 |
| --- | --- | --- |
| 登录后的实验、报告、聊天、分类、线程、更新日志 | `data/data.db` | SQLite；数据按登录账号隔离 |
| 未登录时的本地数据 | `data/offline.db` | 独立 SQLite 数据库 |
| Agent 上传的附件与账号音乐库 | `data/data.db` / `data/offline.db` 的附件表 | 二进制内容保存在 SQLite，不要只备份 `data/uploads/` |
| 旧上传路径兼容文件 | `data/uploads/` | 可能保留历史文件，但不是当前附件的唯一来源 |
| 模型和运行配置 | `config.yaml` 或 `.env` | 可能含 API Key、监听与同步配置 |
| 账号安全、恢复与密钥材料 | `data/_e2ee_accounts.db`、`data/_e2ee_kms.key` | 登录、恢复和同步安全相关，必须妥善保管 |
| 自建同步中继的数据 | 中继的 `RELAY_DB` 或运行目录 | 中继只保存加密同步数据，仍需单独备份 |

数据库的 WAL、SHM 辅助文件在运行时可能存在。不要在程序运行时只复制一个 `data/data.db` 文件并认为这是完整备份。

## 登录数据与离线数据

- 未登录：使用 `offline.db`；
- 登录且令牌有效：使用 `data.db` 中当前账号的数据；
- 登录过期：应用会回到离线数据并要求重新登录；
- 离线数据不会自动变成某个账号的数据，只有用户主动执行离线导入时才会迁移。

多设备同步不合并不同设备上的自由聊天；实验、分析、分类、更新日志、附件和已生成线程按各自同步规则处理。

## 完整备份

1. 先完全退出 ExperMate；
2. 复制整个 `data/` 目录与 `config.yaml`；
3. 如使用自定义 `EXPERMATE_DATA_DIR`，改为备份该目录；
4. 如保留早期上传内容，也已包含在 `data/uploads/`；
5. 如自行部署中继，另外备份中继数据库或中继运行目录；
6. 将备份放在受保护的位置，并记录创建日期和应用版本。

如果必须在程序运行时备份，应使用 SQLite 的一致性备份机制，或同时保留数据库及其 `-wal`、`-shm` 文件；普通用户更建议先关闭应用再复制。

## 恢复原则

- 恢复前先备份当前文件，避免覆盖后无法回退；
- 停止应用后再替换数据库；
- 加密数据库、账号库和密钥材料必须成套恢复；
- 恢复完成后启动应用、登录对应账号，并检查实验、附件和同步状态；
- 同步不能替代离线备份。错误同步、误操作和密钥丢失都可能无法靠中继恢复。

## 不应公开或提交的内容

以下文件或目录可能含个人实验数据、模型密钥或账号安全材料，不能提交到 GitHub、公共网盘或公开聊天：

- `.env`、`config.yaml`；
- `data/` 内的数据库、密钥、旧附件兼容文件和所有 SQLite WAL/SHM 文件；
- 中继数据库与中继 blob 数据；
- 导出的完整备份包。

部署与中继备份见[服务器与同步中继部署](deployment.md)。
