# 服务端数据、备份与恢复

当前业务数据由服务端保存，浏览器不持有离线业务库。默认目录 `data/`；自定义时以服务端进程的运行目录设置为准。

| 内容 | 位置 |
| --- | --- |
| 实验、分析、收藏、线程、主/子会话、压缩历史、日志记录、附件和音乐 | `data.db`，按账号隔离 |
| 模型与运行配置 | `config.yaml`；可能含模型密钥和 JWT 签名密钥 |
| 认证与账号恢复材料 | `_e2ee_accounts.db`、`_e2ee_kms.key` |
| 自定义模板 | `experiment_templates/` |
| 运行日志 | `_logs/`，可能包含实验或对话内容 |

`offline.db` 与旧 `uploads/` 只属于历史数据，当前服务不会初始化或自动读取它们。旧图片导入后保存在附件表，通过账号映射保留旧 URL。

## 完整备份

1. 停止服务端业务进程，确保没有 CLI 或旧服务写入。
2. 复制整个服务端数据目录，并另行备份外置的配置/业务库及部署环境配置。
3. 数据库、账号库、恢复密钥和模型配置须成套保管；备份目录仅授予运维访问。
4. 记录代码版本、日期和数据目录。恢复前也先备份当前目录。
5. 恢复后登录并检查实验计数、附件下载、收藏、主/子会话及历史搜索。

运行中需要使用 SQLite 一致性 backup；不要只复制正在写入的主 `.db` 文件而忽略 WAL。导入工具会使用 backup 保存源库与导入前目标库；它不代替整个账号与配置目录备份。

旧数据按[手动导入步骤](../server-runtime-migration.md#5-手动导入旧-sqlite-工作区)归入指定空账号。导入不改源库，碰撞与错误会回滚，不能覆盖已有账号数据。用户尚未指定归属时保留旧库等待手动导入。

恢复时停止服务，再替换完整目录；启动对应代码版本并验收。当前生成任务没有持久队列，重启只恢复已保存的历史和检查点，不保证继续执行中断的模型任务。

数据库、WAL、SHM、恢复密钥、配置、日志和完整备份不得提交代码仓库。
